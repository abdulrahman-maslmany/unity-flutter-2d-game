## 🏗️ Architecture & Engineering Highlights

This repository implements **Clean Architecture** patterns tailored specifically for cross-platform mobile game engineering:

* **Decoupled Pure Domain Logic:** Gameplay rules (such as `CombatRules`, `LevelProgressionRules`, and `ConnectivityService`) are maintained as pure, headless C# class libraries isolated from Unity's `MonoBehaviour` lifecycle. This allows sub-second test execution (63 tests in ~255ms) via `dotnet test` without booting the Unity editor.
* **Deterministic Dependency Management:** Sealed dependency lockfiles (`packages.lock.json` and `pubspec.lock`) enforced in CI via locked restore flags to eliminate supply-chain drift.
* **Automated Static Code Analysis:** Continuous inspection via **DeepSource** and **Codacy** to enforce Roslyn analyzers, C# nullable references, and strict Flutter lint rules.
* **Security & Secret Hygiene:** Zero hardcoded credentials or production tokens; AdMob integration uses Google's standard test device and ad unit identifiers.
* **Hybrid Inter-Process Bridge:** Clean bidirectional state bridge connecting the Flutter host UI lifecycle with the Unity game view.

> **Note on Generated Files:** The file `Assets/Art/Characters/Player/PlayerInputAction.cs` is automatically generated by the Unity Input System from the `.inputactions` asset. It is marked as `linguist-generated=true` in `.gitattributes` and should not be modified manually.

## 🌟 Key Gameplay Features

* **Dual Combat System:** Melee sword mechanics combined with a physics-based ranged projectile system (Bow & Arrow).
* **Responsive 2D Platforming:** Custom physics-driven character controller handling precise jump curves, variable acceleration, ground checks, and obstacle collision.
* **Collectibles & Progression:** Centralized score tracking, dynamic level unlocking, health containers, and save/load persistence layer (`ISaveStore`).
* **Monetization Architecture:** Clean AdMob integration supporting banner, interstitial, and rewarded ad unit lifecycle events with test-ID fallbacks.

## 2. Core Domain Layer (`Assets/Scripts/Core`)
* **Headless Execution:** Contains zero references to `UnityEngine.MonoBehaviour`.
* **Testability:** Fully testable using standard .NET CLI (`dotnet test Assets/Tests/GameTests.csproj`) without launching graphic buffers.
* **Deterministic Behavior:** Pure input-output functions for hit calculations, gem progression thresholds, and game over states.

## 3. Flutter Host Shell (`my_app`)
* Hosts native UI controls and handles mobile platform capabilities.
* Communicates with the Unity engine via message passing to coordinate game start, pause, level selection, and reward callbacks.
